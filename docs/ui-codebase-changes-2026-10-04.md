Backup e storage mantengono compatibilità con i formati precedenti e includono opzionalmente posizione e preferenze.                                              |
| C4 — Verifiche           | Test DOM con Vitest/Vite e test browser con PDF reale e base path `/paper-reader/`, oltre ai test esistenti. CI su pull request e prima del deploy: lint, formattazione, test, validazione dei paper, build, importazione e Chromium.                                                                                                                                    |
| C5 — Manutenzione umana  | [README](../README.md) per avvio e mappa dei moduli; [CONTRIBUTING](../CONTRIBUTING.md) per modifiche; [CONTEXT](../CONTEXT.md) per il dominio; [development](development.md) per invarianti e importazione manuale senza LLM. Il loader condiviso, lo store recuperabile, il testo PDF e gli ID pubblicati rimangono i confini di riferimento. I test veloci esistenti sono conservati; i nuovi test DOM usano la trasformazione Vite per evitare di estendere il resolver manuale del vecchio harness.

## Verifica

Comandi ripetibili dal repository:

```sh
npm ci
npm run verify
npm run test:import
npx playwright install chromium
npm run test:browser
```

- `verify`: 43 test Node, 7 test DOM, validazione di 11 paper con guide/glossari/approfondimenti, lint, formattazione, TypeScript e build.
- `test:import`: 8 test della pipeline Python.
- `test:browser`: 31 prove: sei percorsi su cinque configurazioni (desktop 1280 px, tablet 1024 px, tablet stretto 768 px, desktop scuro e telefono 390 px), più l'avvio in sviluppo con React Refresh e PDF reale. Include testo a 24 px, PDF lungo, editing durante zoom, ripresa della pagina, glossario da tastiera, ricerca, filtri e annullamento del ripasso.
- Installazione riproducibile dal lockfile con `npm ci --offline`; audit delle dipendenze senza vulnerabilità segnalate al momento della verifica.
- Schermate acquisite e ispezionate; risultati e trace delle prove browser sono locali in `test-results/`, esclusi da Git.

I controlli browser usano Chromium con viewport e dispositivo emulati. Safari, Firefox, screen reader e dispositivi fisici non sono stati provati. Editor testuale e comandi sono navigabili da tastiera; posizionare una nuova nota, disegnare e cancellare le tracce restano gesti sul PDF. Le verifiche non costituiscono una certificazione generale di accessibilità né un benchmark delle prestazioni. La CI è configurata ma non è stata eseguita su GitHub in questa sessione.

Durante l'aggiornamento delle dipendenze, il server di sviluppo rimasto aperto combinava il vecchio plugin in memoria con il nuovo runtime React su disco, causando `RefreshRuntime.getRefreshReg is not a function`. Il processo è stato riavviato sulla stessa porta 5199 con `--force`; la prova development verifica ora l'avvio del lettore reale senza errori JavaScript.
